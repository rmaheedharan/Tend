## Summary
The PR does what the PO asked and nothing else.

**1. Instructions = the PO's exact sentences (rulings 3, 4, 5, 9; GR-1, GR-2).** I extracted the five backquoted lines
from `po-m2-wi16.md` with a script (not by eye) and looked for each as a whole line in the instruction text of every
committed golden body. All 5 are present, in order room, effort, isCritical, isDeepClean, isWeatherDependent, right
after `kind` and before `time`. A line diff of the instructions against `1d1caa3` shows exactly 3 lines removed (old
room, old effort, old combined flag line) and these 5 added. No other instruction line changed. All 9 bodies (3 per
provider) carry byte-identical instruction text. The old wording (`safety or health`, `when the chore belongs there`,
`depends on the weather`) appears nowhere in the repo except the test that checks it is gone.

**2. Goldens were regenerated by the tool and match the builder.** On a clean `git archive` of `02f944e`, I ran
`TEND_PAYLOAD_GOLDEN_OUT=<tmp> swift test --filter PayloadGoldenTests` (swift:6.2-noble, `-warnings-as-errors`, 15 tests
passed). All **21 of 21** written files (9 bodies, 9 heads, 3 allowed lists) are `cmp`-identical to the committed
files. The SHA-256 prefixes match the dev-notes table exactly (bodies `0530a6105c2c` … `ff8733432525`; heads
`5e0624bde48a` / `6f64aadbfc47` / `5b74a96d5a84`; lists `0c642484511e` / `9051458c0aed` / `72f48767fa58`).
I also diffed each body leaf by leaf against `1d1caa3`. Anthropic changes only `$.system` and Gemini only
`$.systemInstruction.parts[0].text`. OpenAI changes only `$.messages[0].content`, which becomes `[0].text` + `[0].type`.
No model ID, schema, fixed member or user-content leaf changed.

**3. GR-3 headers and allowed lists (po-m2-wi10 ruling 4; F1).** Each head gains exactly `User-Agent: Tend` and
`Accept-Language: en-US` after the provider's headers. Each list's `headers` are, in order, auth, the provider's headers,
`User-Agent`, `Accept-Language` (`fixed`), then `Content-Length`, `Host`, `Accept`, `Accept-Encoding`, `Connection`
(`derivedByTransport`). That is exactly the ruling 4 set, with no other header. The PO has confirmed this order (F1).
`keyPaths` and `userContentKeyPaths` are byte-identical for Anthropic and Gemini. OpenAI only loses
`$.messages[].content`. The values are constants with no device data, so ruling 3 tests (1)–(6) hold. The Darwin proof
that explicit values replace the system defaults stays with WI-M2-M4 (see F2).

**4. GR-5 / DN-16-1 (OpenAI system message shape).**
- The system message is now `[{"text": <instructions>, "type": "text"}]`, so no allowed path is both a leaf and a
  container. A new test pins that for all three providers.
- **Can the change hide a user-content shape change? No.**
  - Flattening either the OpenAI system or user content to a string now produces `$.messages[].content`, which is no
    longer in the list. The new `contentShapeChangeLeavesAllowedList` test does this for each slot of each provider.
  - The erased path `$.messages[].content[].text` is now shared by the instructions and the user content. The Linux
    structural check (AC-M2-20 (b)) treats every concrete leaf except `at` = `$.messages[1].content[0].text` as fixed.
    I read `PayloadSentinelSupport.reference`: `fixed = concreteLeaves(body)` minus `userContentAt`. So
    `$.messages[0].content[0].text` is pinned byte for byte to the instructions.
  - The user-content frame finder keys on a literal starting `{"capture":`, which the instructions do not start with.
  - Mutant R7 (user content added as a second part of the system message) is killed by golden bytes, AC-M2-20 (b),
    R28-F6 and D11.
  - The erased device check is blind to extra array elements. That was equally true before this PR, and DN-16-1 states
    it; it is the open element-count ticket (`po-m2-wi11.md` ruling 1, Planner).
- The PO confirmed the change as a fixed-member change under `po-m2-wi10.md` ruling 3 (F2). The condition is that L2a
  runs on these bodies, and `12bd68c` is reverted if a provider rejects the array form. The revert path is recorded in
  DN-16-1.

**5. Tests not weakened.** `git diff 1d1caa3 -- Packages/*/Tests` removes only 5 lines:
- `PayloadOracle.instructionsPath(.openAI)` moves to the new concrete path. The value is still compared to
  `CloudInstructions.text`, so the check is just as strict.
- The hand-written expected header tables of the three providers each gain the two headers and values. This is stricter.

No test was deleted, skipped, disabled or reduced in sample size. Three new tests were added (exact lines, GR-3 lists,
GR-5 shape ×2). The suite count went from 534 to 538.

**6. N-3 and banned words.** I ran my own script over the 18 golden files and 3 lists, testing every 3-digit window of
every digit run: none falls in 600…729. In `CloudOutputSchema.swift`, a regex for overdue, late, missed, failed, behind,
penalty, debt and streak (word starts, case-insensitive) finds no hit. The new lines hold no digit, and the test pins
that too.

**7. Swift 6.** No concurrency surface changed. The additions are two `static let` constant arrays of the existing
`Sendable` header type, plus one local `let`. There is no `@unchecked Sendable`, no `nonisolated(unsafe)`, no force
unwrap and no new dependency. Building with `-warnings-as-errors` is clean. (The R2 mutant first tripped
`[#no-usage]`, which shows the flag is active.)
